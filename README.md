# opc-agent · OPC Radar

个人 AI 技术情报雷达：定时抓取官方博客、技术大牛博客、国内外模型发布（Hugging Face）、开源框架 Release、论文和社区/媒体，经过去重后用 DeepSeek 生成中文摘要、要点分析和重要度，支持一键翻译全文和生成每日简报。情报库以 MCP 工具的形式接入 DeepSeek Harness，Agent 可以直接查询。

## 运行

需要 Node ≥ 22.18，项目没有第三方依赖。PDF 附件需要系统包 `poppler-utils`；扫描版 PDF 的文字识别还需要 `tesseract` 和简体中文语言包（`dnf install -y poppler-utils tesseract tesseract-langpack-chi_sim`）。旧版 Office（doc/xls/ppt）、RTF 和 ODF（odt/ods/odp）需要 LibreOffice（`dnf install -y libreoffice-core libreoffice-writer libreoffice-calc libreoffice-impress`）。

经 Caddy 反代时，附件和知识库上传接口的请求体上限要放宽到 11MB，其余路径保持 10MB：

```
@upload path /api/pm/uploads /api/kb/uploads
request_body @upload {
	max_size 11MB
}
@other not path /api/pm/uploads /api/kb/uploads
request_body @other {
	max_size 10MB
}
```

```sh
bash /opt/start.sh                # 启动 Web（默认 http://127.0.0.1:4180）
npm run hash-password             # 生成 OPC_ADMIN_HASH
npm run radar:run                 # 手动执行一轮采集和分析
npm run brief                     # 在命令行生成今日简报
npm test
```

## 我的关注

动态页第一个标签「★ 我的关注」只显示你选定方向的重点内容（默认重要度 ≥3，可改为只看 ≥4 或全部），设置保存在服务端。简报页勾选「只看我的关注」可以生成聚焦这些方向的简报；24 小时内条目太少时会自动放宽到 72 小时。

主题归类：分析时由模型判定主题，再并上标题/摘要命中的关键词（`autoTag: false` 的主题只认模型判定）。`topics.json` 的主题 id 或名称变化后，历史条目会在下一轮采集时按标题+摘要自动重新归类（每 40 条一次模型调用）。

## 产品顾问（pm-skills）

「产品顾问」页面：输入需求或点子，多选评审方案（点子快评、商业模式与变现、市场与竞争、上市与增长、需求评审、战略红队、PRD 初稿），也可以展开「自选框架」单独勾选任意 pm-skills 框架；所选方案和框架会合并去重，一次最多 6 个，不选即智能匹配；可以勾选「结合雷达情报」引用库里的相关动态。评审在后台进行，通常 30 秒到 2 分钟；结果和历史保存在数据库中。

首版出来后可以在同一会话里继续对话：提问会得到简短回答，提出修改（如「定价部分按 To B 年费重写」）会生成新版本文档；勾选「改写文档」可强制改写。每个版本都可以切换查看、在 Markdown 原文上手动编辑（保存为新版本，之后的对话基于它）、下载 `.md`，或打开打印页用浏览器「打印 → 另存为 PDF」。会话、对话和全部版本都保存在本机数据库里。

版本对比：查看 v2 及以后的版本时点「对比上一版」，或在对话里的「已生成 vN」、手动保存后的提示上点「查看改动」，即可看到相对上一版的逐行差异；也可以在对比栏里任选两个版本。默认只看改动（未改动的行折叠，可逐段展开），也可切换为显示全文；一行内改动的文字用深色标出。

篇幅上限：需求和追问最多 8000 字；首版评审按 6000 字（选 4 个以上框架时 9000 字）撰写，输出上限 12000–16000 tokens；改写文档输出上限 16000 tokens；对话回答最多 3000 字；文档最长 8 万字；单次模型调用超时 10 分钟。模型输出达到上限时会自动从断点续写，最多 2 次；仍未写完时，版本说明标注「输出达到上限，内容可能不完整」，回答末尾也会注明。

### 附件

新建评审和追问都可以带附件：点「添加附件」、把文件拖到表单上，或在输入框里直接粘贴截图。有附件时需求或追问文字可以留空。

- **格式**：图片 png、jpg、gif、webp；PDF；Word doc、docx、docm、rtf、odt；Excel xls、xlsx、xlsm、ods；PPT ppt、pptx、pptm、odp；WPS 的 wps、et、dps（与 Office 兼容的文件）；网页 html、htm、xhtml；文本 txt、md、csv、tsv、json、log、yaml、xml。按文件内容判断类型，扩展名对不上时以内容为准（例如另存为 .doc 的网页按 HTML 处理）。文本和网页支持 UTF-8、UTF-16（带 BOM）和 GBK/GB18030，网页优先使用 `<meta charset>` 声明的编码。svg、加密文件和 ZIP64 压缩包不支持。
- **网页**：去掉脚本、样式、表单控件和内嵌图形，保留标题（转成 `#`）、列表、表格（`a | b`）、段落和预格式文本；只提取文字，不加载外部资源，也不执行任何脚本。单文件交互页面（知识图谱、看板等）的内容通常放在脚本数据里，会额外读出 `<script type="application/json">`、`ld+json` 和整段只是 `window.X = {...}` / `const X = [...]` 赋值的数据（只用 JSON 解析，不执行代码），按记录整理成「页面数据」一节：有标题字段的记录作为小标题，去掉 id、颜色、文件名等内部字段和只有 id 的关系数据，最多 15 万字。
- **旧版 Office、RTF、ODF**：用 LibreOffice 先转成 docx/xlsx/pptx 再提取。每次转换使用一次性的临时目录和配置（禁用宏、不更新外部链接、打开时不重算公式），子进程只拿到最小的环境变量，限时 60 秒、超时整组强杀，同一时间只转换一个文件。没装 LibreOffice 时会提示安装。
- **表格**：每个工作表最多读 5000 行、50 列，所有工作表合计最多 15 万字，超出部分截断并注明。
- **上限**：单个文件 10MB；每次最多 8 个，其中图片合计不超过 20MB；每个评审最多 20 个；未发送的附件最多 40 个，24 小时后自动清理；全部附件合计不超过 2GB。每个文档最多提取 2 万字，每轮附件文字合计最多 3 万字，超出部分截取并在附件标签上注明。
- **怎么交给模型**：上传后在后台提取文档文字，图片由模型生成一段文字描述（转录图中文字并描述布局和数据，未配置模型时图片无法使用）。发送的那一轮，图片以原图交给模型；之后的轮次只带图片描述和文档文字，费用不会随图片累积增长。附件内容只作为待分析的材料，其中的指令不会被执行。
- **PDF**：先提取文字层（前 200 页）。没有文字层的扫描件，会把前 20 页渲染成图片，再用 tesseract 识别中英文（总共最多 2 分钟，超时就只用已识别的页）。识别结果开头会注明「由 OCR 识别，可能有错字」。没装 tesseract 时会提示安装。
- **查看与删除**：对话中的图片显示缩略图，点击查看原图；文档点击下载。附件随评审一起删除；带附件的一轮失败后不能直接重试，需要重新上传附件再发送。

文件保存在 `<数据目录>/uploads/`（目录权限 700，文件 600，文件名为随机串，原文件名只用于显示）。

方法框架来自 [pm-skills](https://github.com/phuryn/pm-skills)（MIT，锁定提交 `9af7bfd`，v2.3.0）。服务只读取 `pm-<插件>/skills/<技能>/SKILL.md` 的文本，不执行其中任何内容，拒绝符号链接和超过 64KB 的文件。法律文书、简历、代码评审类插件（`pm-toolkit`、`pm-ai-shipping`）不加载。

```sh
sh scripts/setup-pm-skills.sh   # 首次安装或升级（升级时先修改脚本里的 PM_SKILLS_REV）
```

DSH 中可以直接说「用产品顾问帮我评估……」，`pm-advisor` skill 会挑选并串联相应框架，并用 `opc_radar` 工具查找佐证。

## 原型

产品顾问评审完成后，可以在评审页右下方的「原型」面板里，把 PRD 变成可点击的手机/桌面端原型。

- **生成**：点「生成原型」按当前查看的 PRD 版本生成；PRD 有新版本时，面板会提示「原型基于 PRD vN，PRD 已更新到 vM」，可一键按新 PRD 重新生成。生成中显示进度，每 2 秒刷新一次；页面有改动不会丢失进度。
- **修改**：在「描述要怎么改原型……」里写 1–1000 字，例如「登录页加一个微信登录」。服务先规划改动，只重新生成相关页面，其余页面原样复制到新版本；也可以基于旧版本再次修改。失败版本可用「重试」原地重跑。
- **预览与标注**：面板内可直接切换页面、手机/桌面、打开「标注」开关。标注模式下每页顶部显示该页的用途与内容说明，可点击元素带虚线提示，右侧有页面地图；全屏页（` /proto/<评审 id>/<版本 n>`）也支持同样的操作。
- **导出**：「下载」得到单文件 HTML，包含内联样式与脚本、`<meta>` CSP 和 SHA-256 脚本哈希，可直接发给别人预览；「全屏」在新的页面里打开同一版本。
- **上限**：PRD 用于大纲最多 2.4 万字、用于单页最多 1.2 万字；3–10 页；单页清理后 40KB、整份文档 400KB；单页 6000 tokens/180 秒，单任务 8 分钟；页面并发 3、全站原型任务并发 2、每个评审同时 1 个；每个评审最多 20 版，`v1` 永久保留。
- **安全**：模型输出的 HTML 经白名单清理后才入库，脚本、事件属性、外链和外发请求被移除。预览 iframe 只用 `allow-scripts` 沙箱，响应头 CSP 限制脚本为文件自带哈希，并带 `frame-ancestors 'self'`；页面下拉框和标注开关只处理来自本 iframe 的消息。下载文件名会去掉非法字符。

没有配置 `DEEPSEEK_API_KEY` 时，生成、修改和重试都会返回 503。

## 合规

「合规」页按产品管理国内上线所需的备案与许可。新建产品时可以从产品顾问评审带入描述，评审页也有「做合规自查」入口。

- **问卷与判定**：14 道题（形态、受众、收费、AI 用法、公开传播、情感陪伴、用户规模、个人信息、未成年人、数据出境等），由规则表判定 17 个事项：ICP 备案与经营许可、APP 备案、公安联网备案、等保、大模型登记与备案、算法备案、双新评估、模型公示、AI 内容标识、拟人化自查与评估、隐私政策、个人信息保护影响评估、数据出境、未成年人保护。结果分为「必须办」「可能需要」「不适用」，每项列出主管部门、法规依据、触发理由和官方入口。结果为自查参考，以属地主管部门口径为准。
- **模型补充**：「AI 预填」按产品描述预填未答的题，每题注明依据，需逐题确认后才能判定；「可能需要」的事项可以「请顾问解释」。模型不参与判定。未配置 `DEEPSEEK_API_KEY` 时这两项不可用，问卷和判定照常。
- **台账**：判定后事项自动进入台账，可记录状态、编号、办结日期、到期日、提醒日和备注。重新判定只增补新事项，不覆盖已填内容；不再适用的事项标出，由你确认「不适用」或「保留」。ICP 经营许可办结后自动推算 5 年到期日和次年年报提醒，等保推算次年测评提醒。30 天内到期或已逾期的事项在菜单上显示角标。
- **监管动态**：情报新增「合规监管」分组，采集网信办「网信发布」「政策法规」两个栏目；合规页的「监管动态」直接跳转到该分组。

规则在 `packs/compliance/rules.ts`，法规条款按官方原文核对；规则改动时提升 `RULES_VERSION`。

### 材料起草

按判定结果和资料起草 10 种材料：隐私政策、用户协议、算法公示内容、模型公示文案、未成年人保护说明（对外公示），应用说明（登记/备案用）、算法安全自评估报告、双新安全评估报告、拟人化安全评估报告、AI 生成内容标识方案（备案提交）。判定为不需要的材料不能起草，并注明原因。

- **资料**：左侧「主体信息」填写公司全称、信用代码、联系方式、个人信息保护负责人等，所有产品共用；产品的「资料」标签填写对外名称、投诉渠道、生效日期、模型、数据存放地与保存期限、第三方 SDK 列表等。页顶列出未填的项和受影响的材料。
- **起草**：每份材料由模板章节组成。固定章节（引言、SDK 表、联系方式等）按模板和资料直接写好；其余章节由模型按写作要点逐章起草（「生成剩余章节」逐章进行，单章失败可重试）。缺的信息一律写成【待填：字段名】并高亮；模型输出会去掉一二级标题、截到 6000 字，资料里没出现过的网址会被删除。
- **编辑与版本**：每章可手工编辑（Markdown）、重新生成、查看历史版本与差异、回退；每章保留最近 50 个版本。资料或问卷答案变化后，受影响的章节标为「资料已更新」；不再适用的条件章节标为「模板已移除」，不导出，可删除。
- **定稿与导出**：还有未生成章节或【待填】内容时不能定稿，会列出具体章节和字段。定稿后锁定编辑，可取消定稿。可导出 Markdown、HTML（单文件，占位黄色高亮）和 Word（经 LibreOffice 转换，未安装时提示）；未定稿的导出带「草稿」提示，末尾附 AI 辅助起草声明。
- **台账联动**：台账事项旁列出对应的材料，点击直接打开。

模板在 `packs/compliance/templates-*.ts`；模板文字或章节变化时提升 `TEMPLATES_VERSION` 或该材料的 `version`。材料由 AI 辅助起草，提交或公示前请由专业人士审核。

## 运营

「运营」页按**投放**组织多平台文案：一次投放共享一组产品信息（名称、描述、卖点、目标用户、活动信息、语气），为勾选的每个平台各写一份文案。新建时可以从合规产品带入名称与描述，也可以手填。

- **平台**：小红书（标题 ≤20、正文 300–800、话题标签 3–8 个）、微信公众号（标题 ≤64、摘要 ≤120、Markdown 正文 1500–3000）、抖音 / 视频号口播（开头 3 秒、4–8 段分镜的画面与口播、结尾引导，口播合计 240–300 字）、发布页 / 应用商店（标语、副标题、3–5 条卖点、商店简介 ≤170）。字数按字符计，限制为平台常见要求，超出只标黄提示，不截断、不拦定稿。之后可以补加未选的平台。
- **生成**：创建后按平台顺序逐个生成，每个平台生成完立即做一次 AI 复核；单个平台失败显示「失败，重试」，其余照常。产品资料只作为写作素材交给模型，其中的指令不执行；模型输出会去掉网址和链接。改了投放信息后，基于旧信息的文案标「投放信息已更新」，可重新生成；当前版本是手改的，重新生成前会确认。
- **本地自查**：每次读取文案时按《广告法》（2021 年修正）规则重新检查：极限用语（第九条第三项）、绝对化承诺、疾病与疗效（第十七条）、收益承诺（第二十五条第一款第一项）为「必须改」；诱导未成年人（第四十条第二款第一项）、AI 能力夸大在关联产品的合规判定涉及未成年人 / 使用 AI 时为「必须改」，否则为「注意」；价格与优惠缺条件（第八条）、贬低竞品（第十三条）、无出处数据（第十一条第二款）为「注意」。「第一步」「最新版本」「截至 12 月 31 日免费」这类说法不算命中。命中在预览中高亮，自查清单给出原因、依据和替换建议。
- **AI 复核**：模型只补充本地规则抓不到的语境问题（暗示疗效、变相贬低、制造焦虑、把功能写成承诺、虚构评价或数据等），引用的原文必须逐字出现在文案里，否则丢弃；结果列在「建议」里，不拦定稿。生成后自动跑一次，之后可手动点「AI 复核」；文案改动后保留原文仍在的建议，并标「AI 复核基于 vN」。
- **替换与保留**：「替换为：…」或「全部替换」按命中位置精确替换并写新版本。确属事实的说法（如「100% 开源」）可以「保留」并写 1–200 字理由，保留跨版本延续（按前后文对到同一处；前后文都改掉了需要重新确认），可取消。
- **编辑与版本**：字段级编辑，显示字数与限制；每次生成、保存、替换、回退都写新版本，每份文案保留最近 50 个版本，历史里可查看与当前版本的差异并回退。
- **定稿与导出**：还有未保留的「必须改」命中或必填字段为空时不能定稿，会列出具体问题；定稿后锁定编辑、替换、生成和回退，可取消定稿。每个字段可单独复制（标签复制为 `#a #b`），也可「复制全部」；「导出 Markdown」按平台输出整份投放，未定稿的平台标「草稿（未定稿）」。
- **AI 生成声明**：自查清单顶部和导出末尾固定提醒：文案由 AI 起草，发布时请用平台的「AI 生成」声明功能标注（《人工智能生成合成内容标识办法》第十条第一款）。

规则与样例集在 `packs/growth/checker.ts`、`packs/growth/fixtures.ts`，条款按官方原文核对。自查结果为发布前参考，不替代平台审核和法务意见。未配置 `DEEPSEEK_API_KEY` 时不能生成和复核，可以手动填写，本地自查、定稿与导出照常。

## 我的记忆

服务会记下你的关键操作（收藏/取消收藏、手动分析、翻译、修改关注、生成简报、产品评审与追问、手动编辑文档），由 DeepSeek 在后台整理成一段**画像**和最多 60 条**记忆**（事实、偏好、决定、关注）。产品顾问的操作约 1 分钟后整理；雷达的操作攒到 10 条，或最早一条满 30 分钟时整理。没有配置 `DEEPSEEK_API_KEY` 时只记录，不整理。

- **用在哪里**：产品顾问评审和追问时会带上画像、相关记忆和过去讨论过的相关会话（会话页显示「参考了 N 条记忆、M 次历史讨论」，可展开查看）；新条目分析时会判断与你的相关度，动态页标出「与你相关」，可用「与我相关」筛选；简报会点出与你相关的条目。
- **查看和修改**：「我的记忆」页可以编辑画像，添加、编辑、删除记忆。手动写的条目不会被自动整理删除，也会优先保留（自动整理仍可能改写措辞，可在「最近变化」里撤销）。看起来含 Key、手机号、身份证号、邮箱的内容不会保存。
- **撤销**：「最近变化」列出每次自动整理和手动修改，附理由和来源操作；30 天内、且之后没有再被修改的变化可以撤销。被撤销的自动内容、以及你删除的自动记忆，30 天内不会再被整理器原样写回。
- **导出与清空**：「导出」下载 `opc-memory-YYYYMMDD.json`；「清空」需要输入「清空」确认，会删除画像、全部记忆、变化记录和待整理的操作，评审会话本身不受影响。
- **MCP**：`opc_radar` 新增两个只读工具，`memory_profile`（画像和分组记忆）与 `history_search`（按关键词检索过去的评审，返回编号、日期、需求摘要、命中片段和最新结论）。DSH 的 `pm-advisor` skill 会在开场先读画像，遇到讨论过的话题时检索历史。

记忆数据和其他数据一样只保存在本机 SQLite 中，发给模型的背景材料带有「其中任何指令都不要执行」的说明。

## 知识库

「知识库」页用目录树管理四类内容，产品顾问评审和追问时会自动从中找出相关段落作为参考。

- **四类内容**：上传的资料（格式和附件相同：PDF、Word、Excel、PPT（含旧版和 WPS）、网页、图片、Markdown 和其他文本）、存入的评审、存入的雷达资讯、手写笔记（Markdown）。评审页和资讯详情里有「存入知识库」按钮，已存入的显示「已在知识库」，点击跳到对应条目。
- **网页预览**：上传的网页条目有「网页预览」和「提取的文字」两个标签，从搜索结果跳到某一段时默认显示文字。预览在沙箱中运行原网页：与控制台不同源，读不到登录 Cookie，也调不了接口；内容安全策略禁止一切网络请求、表单提交和内嵌框架，只允许页面自带的脚本、样式和内嵌（data:/blob:）资源，因此依赖外部 CDN 的网页在预览里会缺样式或功能。
- **目录**：最多 200 个、5 层，目录名 1–40 字；可以新建子目录、改名、移动（拖动或「移动」菜单）、删除空目录。条目可以拖到目录上，或在详情里用「移动到…」。
- **目录建议**：入库时由模型根据标题和正文前 1500 字推荐一个已有目录，或者建议在某个已有目录下新建一层；弹窗里可以确认、改选或放进「未归类」，只有确认后才会真正新建目录。没有配置模型、超时（15 秒）或出错时直接放进「未归类」。
- **跟随最新版**：评审和资讯条目只记来源，不存正文。搜索、打开条目和评审召回之前会检查来源是否有新版本（评审改出新版、资讯补了翻译或分析），有就重新切块；来源被删除后条目显示「来源已删除」，正文清空，只能移动或删除。
- **搜索**：按标题和正文全文搜索，每个条目显示最相关的一段；少于 3 个字的词（如「AI」）改用包含匹配。
- **评审召回**：首版评审和每轮追问都会用当前输入检索知识库，最多取 5 段、每个条目最多 2 段、合计约 2500 字，放进提示词里的 `<kb_excerpts>` 块（另计预算，不占记忆的 3000 字）。会话页的「参考了」一栏会多出「N 段知识库」，可以点击跳到对应段落；条目已删除时显示「（已删除）」。召回出错只记日志，不影响评审。
- **上限**：条目 2000 个；上传和笔记正文各 20 万字；单个文件 10MB，所有上传文件合计 1GB；每个条目最多索引 400 块（约 32 万字），超出时详情页提示「过长，只索引了前面部分」。
- **存储**：上传的原文件保存在 `<数据目录>/kb/`（目录权限 700，文件 600，文件名为随机串）。删除条目时原文件一并删除。
- **MCP**：`opc_radar` 新增两个只读工具，`kb_search`（返回 `#docId 目录/标题 › 小节｜命中片段`，最多 10 条）与 `kb_doc`（标题、目录、来源和正文，每页 8000 字）。MCP 不触发来源刷新，评审类条目读到的可能不是最新版本。

## 知识库 Wiki

知识库里的资料会由模型在后台整理成一套互相链接的 Wiki 页面（总览、实体、概念、对比、问答、资料摘要），每句结论都标出原文出处。知识库页顶部有四个标签：资料 / Wiki / 问 Wiki / 体检与日志。

- **摄入**：服务每 2 分钟扫描一次，状态为就绪、还没编入或正文有变化的资料会自动排队编入；失败的最多自动重试 3 次。每份资料先规划要新建或更新哪些页面（一次最多 15 页），再按每批 3 页撰写，超过 10 万字的资料先分块提炼要点。有评审、追问或原型在生成时，Wiki 任务会让路。资料详情里也可以手动点「编入 Wiki」。
- **页面语法**：`[[slug|显示文字]]` 是页面链接，`[^资料id:段号]` 是原文出处，`![](asset:N)` 是图片。写入时，指向不存在段落的出处会被删掉；用标题而不是 slug 写的链接会自动改成对应页面。已有页面的新正文不到旧正文一半时，保留旧正文，把新内容追加到「## 新增信息」。
- **编辑与版本**：页面可以手动编辑，也可以上传图片（png/jpg/gif/webp，单张最大 5MB）插入正文。每页保留最近 50 个版本，可以查看与当前版本的差异，或恢复到某个版本。
- **问 Wiki**：基于 Wiki 页面和它们引用的原文回答，问题最多 500 字。回答可以「存为问答页」，之后的摄入会把新资料补充进去，页面类型仍然是问答。
- **体检**：每周一 03:00 后自动做一次，也可以手动发起，检查缺页、孤立页、失效出处、资料更新后没同步的页面、没有出处的页面、提到了却没加链接、页面之间的矛盾，并给出缺口建议。补链接、按标题修正链接、删除失效出处这几类会自动修复；缺页可以点「生成此页」，由模型依据链接到它的页面引用的原文来写。
- **撤销**：摄入、自动修复、生成缺页、存为问答、编辑和恢复版本都可以在「体检与日志」里撤销。涉及的页面之后被改过时会提示冲突，确认后可以强制撤销。被撤销的资料不会再自动编入，需要手动点「编入 Wiki」。
- **评审召回**：产品顾问评审和追问时，先取最相关的 3 个 Wiki 页面（约 1500 字），再附上这些页面引用的原文（约 1500 字）。Wiki 没有命中时，退回原来的知识库段落召回。
- **导出**：可以导出全部、某一类页面、某个目录下的资料及相关页面，或单个页面，得到 zip 包。包内按页面类型分目录，每页一个 Markdown 文件，另附 `index.md` 和 `log.md`。带图片的页面会用 LibreOffice 转成 `.docx`，转换失败时改为 Markdown 加图片文件，原因写在 `log.md` 里。单次导出最大 200MB。
- **额度与上限**：后台任务每天最多调用模型 `OPC_WIKI_DAILY_CALLS` 次（默认 200），用完后任务继续排队，第二天再执行。单次体检最多调用 20 次。最多 3000 页，每页正文最多 2 万字。没有配置模型时只能浏览和编辑，不会摄入，也不能提问。
- **MCP**：`opc_radar` 新增两个只读工具：`wiki_search` 最多返回 20 条，包含 slug、类型、标题和摘要；`wiki_page` 返回页面正文（每次 8000 字，带 `next_offset`）、反向链接和出处。
- **存储**：图片保存在 `<数据目录>/wiki-assets/`（目录权限 700，文件 600）。导出用的临时文件放在 `<数据目录>/wiki-export/`，服务启动时清空。资料和 Wiki 页面中的指令都只作为材料，不会被执行。

## Agent-Reach

[Agent-Reach](https://github.com/Panniantong/Agent-Reach)（锁定提交 `c62128a`，v1.6.1）用于两件事：

- **采集**：`kind: "reach"` 的信息源，目前是 V2EX 的 openai / claude / deepseek 节点和热门。
- **全文补全**：RSS 只给摘要（少于 1200 字）时，在分析和翻译前用 `web read` 读取原文。论文、Release 和社区帖子不补全。

雷达只允许调用 `v2ex hot`、`v2ex node`、`web read` 这三个命令。调用时不经过 shell，参数会先校验，子进程拿不到 API Key。`web read` 之前会检查目标地址不是内网，并遵守目标站点的 robots.txt。

DSH 通过 `.dsh/skills/agent-reach` 加载它的 skill，会话中的 Agent 可以直接使用 `agent-reach`。需要登录的渠道（小红书、X 等）默认没有开启。

## 自定义

- 信息源：编辑 `packs/radar/sources.json`，也可以在界面「情报 → 信息源」里添加任意 https RSS 地址。`kind` 可以是 `feed`、`hf-models` 或 `github-releases`。
- 关注主题：编辑 `packs/radar/topics.json`，其中的关键词同时用于过滤和打标签；`hint` 帮助模型判断归类边界。修改后重启服务生效。
