# Wiki 分类树（左侧结构化）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wiki 左侧改为「领域 → 主题 → 页面」的可折叠分类树；新资料摄入时随规划一并分类；可一键整理现有页面；支持最小的手动调整。

**Architecture:** 新增 `packs/wiki/tree.ts`（节点与页面归属的存储、路径解析、整理与快照撤销，迁移 16）；`ingest.ts` 的规划提示词带上分类树并读取每页 `path`，不增加模型调用；`queue.ts` 增加 `organize` 任务；`wiki-api.ts` 增加节点与整理接口；前端改 `wiki.js` 的左栏与页面头部。

**Tech Stack:** Node 22 + TypeScript（直接运行）、`node:sqlite`、`node:test`、原生 JS 前端；无第三方依赖。

**Spec:** `docs/superpowers/specs/2026-11-24-wiki-tree-design.md`

## Global Constraints

- 不引入第三方依赖；模型只走 `packages/core/llm.ts` 的 `Llm`；调用统计走现有 `Calls`（`packs/wiki/ingest.ts`）。
- 迁移只追加在 `packages/core/db.ts` 的 `MIGRATIONS` 末尾，本期为 16；所有断言 `user_version` 为 15 的测试改为 16（10 个文件：`packs/pm/attach-prompt.test.ts`、`packs/pm/attachments.test.ts`、`packs/memory/migrate.test.ts`、`packs/memory/skills.test.ts`、`packs/kb/expand.test.ts`、`packs/kb/migrate.test.ts`、`packs/proto/store.test.ts`、`packs/wiki/migrate.test.ts`、`packs/compliance/store.test.ts`、`packs/growth/platforms.test.ts`，先用 `grep -rn "user_version" --include=*.test.ts packs apps mcp packages` 核对实际清单）；`packs/pm/pm.test.ts:218` 与 `packs/memory/migrate.test.ts:10` 的回滚 DROP 列表补上 `wiki_node_undo`、`wiki_page_node`、`wiki_nodes`（先删依赖者）。
- SQL 一律参数绑定。提示词中的页面标题、节点名等用户 / 模型文本经 `fence()`（`packs/memory/events.ts`）。前端用户 / 模型文本只经 `textContent` 或 `h(..., { text })`。
- 错误文案固定中文；`WikiError(status, msg)` 映射为同状态码。
- 数值（设计原文）：节点最多 200 个、最深 3 层、名称 1–40 字（NFKC、去首尾空白、同级不区分大小写不重名）；一次摄入最多新建 5 个节点；整理每批最多 100 页、最多 10 次调用；删除节点只允许空节点；资料摘要页固定放进系统节点「资料摘要」，问答页放进「问答」；`localStorage` 键 `opc.wikiTree`。
- 每个任务：先写测试并确认失败 → 实现 → 相关测试通过 → `sh /tmp/opc-check-ui.sh` 输出 `# fail 0`、`TSC_OK`（页面模拟测试已并入 `npm test`）→ 提交（作者 `andrewlayuan <andrewlayuan@users.noreply.github.com>`）。
- 分支：`feat/wiki-tree`，完成后快进合并到 main。

## Review Focus

1. 模型返回的 `path` 不是数组、含非字符串、空串、超过 3 层、名称含 `/` 或控制字符、与已有节点只差大小写 / 全半角 → 不报错、页面照常写入，按规则截断 / 复用 / 回退未分类。Task 2 加测试。
2. 整理时模型漏掉部分 slug、重复列出同一 slug、列出已软删除或手动放置的页面、编造不存在的 slug → 漏掉的保持原状，重复取第一次，其余忽略，手动的不动。Task 3 加测试。
3. 整理的模型输出无法解析或调用失败 → 分类完全不变、操作记为失败、可重试，不留下半个结果。Task 3 加测试。
4. 节点数已达 200 个时摄入 → 页面照常写入，只是不新建节点、放到已匹配的最深一层。Task 2 加测试。
5. 页面被软删除再恢复、或被整理 / 撤销整理后，页面数统计与树里的显示一致（只数未删除页面）。Task 1、Task 3 加测试。

**Interfaces:**
- Consumes: `tx`（`store.ts`）、`WikiError`、`WIKI_LIMITS`。
- Produces（`tree.ts` 导出，后续任务只依赖这些签名）：
  - `interface TreeNode { id: number; parent_id: number | null; title: string; sort: number; manual: boolean; own: number; total: number }`
  - `listNodes(db: DB): TreeNode[]`：全部节点，`own` 为直属未删除页面数，`total` 含子孙；按 `sort, id` 排序。
  - `pageNodes(db: DB): Map<number, { node_id: number; manual: boolean }>`：按 `page_id`。
  - `cleanNodeTitle(raw: unknown): string`：NFKC、去控制字符与首尾空白、折叠空白、截 40 码点；空串表示不合法。
  - `ensurePath(db: DB, path: string[], o?: { manual?: boolean; budget?: { left: number }; now?: number }): number | null`：逐层匹配同名（NFKC 后不区分大小写）节点，不存在才新建；超过 3 层截断；`budget.left` 为剩余可新建数，用完后返回已匹配到的最深一层（一层都没有返回 `null`）；节点总数到 200 时同样停止新建。
  - `placePage(db: DB, pageId: number, nodeId: number | null, o?: { manual?: boolean }): void`：`nodeId` 为 `null` 删除归属；`manual` 默认 `false`。
  - `createNode(db: DB, title: unknown, parentId: number | null, now?: number): number`：`manual = 1`；父节点不存在 404「节点不存在」，深度超限 400「最多 3 层」，重名 409「同级已有同名节点」，总数超限 400「最多 200 个节点」，名称不合法 400「名称需在 1–40 字之间」。
  - `renameNode(db: DB, id: number, title: unknown): void`：置 `manual = 1`，错误同上。
  - `deleteNode(db: DB, id: number): void`：非空 409「节点下还有内容」（有子节点或有未删除页面；只挂着已软删除页面的节点视为空，同时清掉这些归属行）。
  - `systemNode(db: DB, title: '资料摘要' | '问答'): number | null`：取或建顶层系统节点（`manual = 0`）；总数超限时返回 `null`。
